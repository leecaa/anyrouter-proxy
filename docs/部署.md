# AnyRouter Proxy 部署文档

## 配置说明

配置文件路径：`~/.config/anyrouter-proxy/proxy_config.json`

```json
{
    "api_key": "sk-your-anyrouter-api-key",
    "proxy_url": "http://127.0.0.1:7890",
    "use_proxy": false,
    "debug": false,
    "target_base_url": "https://anyrouter.top",
    "host": "127.0.0.1",
    "port": 8765,
    "dashboard_password": "your-dashboard-password",
    "dashboard_secret": ""
}
```

### 关键配置项

| 字段 | 说明 | 注意事项 |
|------|------|----------|
| `api_key` | AnyRouter API 密钥 | 必填，从 AnyRouter 后台获取 |
| `target_base_url` | **上游 API 地址** | **推荐 `https://anyrouter.top`，含或不含 `/v1` 均可** |
| `use_proxy` | 是否使用 HTTP 代理 | 国内服务器设为 `false`，本地开发设为 `true` |
| `proxy_url` | HTTP 代理地址 | 仅 `use_proxy=true` 时生效 |
| `host` | 监听地址 | 配合 Nginx 反代时用 `127.0.0.1` |
| `port` | 监听端口 | 默认 `8765` |
| `dashboard_password` | Dashboard 登录密码 | 必填，用于 Web 管理界面 |
| `dashboard_secret` | Session 签名密钥 | 留空，首次启动自动生成 |
| `debug` | 调试模式 | 生产环境设为 `false` |

> **`target_base_url` 支持含或不含 `/v1` 后缀，代理会自动规范化。** 推荐使用 `https://anyrouter.top`（不含 `/v1`），以兼容 NewAPI 等网关的 BaseURL 配置。

## 支持的模型

| 模型 | 类型 |
|------|------|
| `claude-3-5-haiku-20241022` | Haiku |
| `claude-3-5-sonnet-20241022` | Sonnet |
| `claude-3-7-sonnet-20250219` | Sonnet |
| `claude-haiku-4-5-20251001` | Haiku |
| `claude-opus-4-1-20250805` | Opus |
| `claude-opus-4-6` | Opus |
| `claude-sonnet-4-20250514` | Sonnet |

Sonnet/Opus 模型会自动附加 Claude Code 请求格式（`anthropic-beta`、`tools`、`system`、`thinking`）。

## Linux 部署（PM2 方式）

### 前置条件

- Python 3.10+
- PM2（`npm install -g pm2`）
- Nginx（反向代理 + HTTPS）

### 1. 克隆仓库

```bash
cd ~/github
git clone git@github.com:your-github-username/anyrouter-proxy.git
cd anyrouter-proxy
```

### 2. 创建虚拟环境

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

### 3. 配置

```bash
mkdir -p ~/.config/anyrouter-proxy
cp proxy_config.example.json ~/.config/anyrouter-proxy/proxy_config.json
```

编辑配置文件，填入 `api_key` 和 `dashboard_password`。

**确保 `target_base_url` 为 `https://anyrouter.top`（推荐不含 `/v1`）。**

### 4. 启动（PM2）

```bash
pm2 start .venv/bin/python --name anyrouter -- main.py --host 127.0.0.1 --port 8765
pm2 save
```

### 5. Nginx 反向代理

```nginx
server {
    listen 443 ssl http2;
    server_name anyrouter.your-domain.com;

    ssl_certificate /etc/letsencrypt/live/anyrouter.your-domain.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/anyrouter.your-domain.com/privkey.pem;

    location / {
        proxy_pass http://127.0.0.1:8765;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;

        # SSE streaming support
        proxy_buffering off;
        proxy_cache off;
        proxy_read_timeout 600s;
        proxy_send_timeout 600s;
    }
}
```

### 6. 验证

```bash
# 健康检查
curl https://anyrouter.your-domain.com/health

# 查看配置（API Key 脱敏）
curl https://anyrouter.your-domain.com/config

# Dashboard
open https://anyrouter.your-domain.com/dashboard
```

## Claude Code 客户端配置

在 Claude Code 或其他客户端中配置：

```
API Base URL: https://anyrouter.your-domain.com/v1
API Key: 任意值（代理会用配置中的 api_key 覆盖）
```

代理会自动：
- 使用 Chrome TLS 指纹（curl_cffi impersonate=chrome）
- 注入 Anthropic Python SDK 0.84.0 请求头
- 为 Sonnet/Opus 模型添加 Claude Code beta 标志和 tools/system
- 过滤请求体，只保留安全字段

## ⚖️ 生产与开发调试环境隔离规范

根据最新架构，AnyRouter 代理服务明确区分为**生产**和**开发调试**两套独立的环境：

### 1. 生产环境 (Production)
- **代码目录**：`/home/ubuntu/github/anyrouter`
- **监听端口**：`8765` (127.0.0.1)
- **管理方式**：常驻运行在独占的 `anyrouter-proxy` tmux 会话中。
  - 启动命令：`tmux new-session -d -s anyrouter-proxy "/home/ubuntu/github/anyrouter/.venv/bin/python /home/ubuntu/github/anyrouter/main.py"`
- **公网反代**：由 Nginx 将公网域名 `https://anyrouter.your-domain.com` 代理至本地 `8765` 端口（支持完整的 SSE 流式与 600s 慢长连接超时）。
- **主要特征**：包含完整的 API Key 轮询池、Claude Camouflage 伪装与 Dynamic Outbound 转发，为下层网关（如 NewAPI）提供稳定可靠的模型路由。

### 2. 开发调试环境 (Development)
- **代码目录**：`/home/ubuntu/github/anyrouter-proxy`
- **建议端口**：`8766`（避开生产端口）
- **运行方式**：可使用独立的 `anyrouter-dev` tmux 会话或直接在终端前台运行，用于二次开发、补丁测试及 PR 验证。
  - 启动命令：`ANYROUTER_PROXY_CONFIG=~/.config/anyrouter-proxy/proxy_config_dev.json /home/ubuntu/github/anyrouter-proxy/.venv/bin/python /home/ubuntu/github/anyrouter-proxy/main.py --port 8766`

## 📝 历史重大升级记录 (2026-05-29)

已在生产环境成功重构并应用以下两项 SRE 特性：
1. **模型完全透传机制**：
   - 彻底移除了先前硬编码客户端模型为 `claude-opus-4-7` 的 Override 策略和 silent fallback。
   - 客户端请求什么模型，代理就以什么模型转发至 `anyrouter.top/v1/messages`，如实透传。如果上游接口返回 `503` 等熔断/不可用状态，在 0.1s 内秒级直接将最真实的 error_response 透传并返回给客户端，从物理上杜绝重试导致的慢速假死或 502 Network Error。
2. **Dashboard 两步实时测试架构**：
   - 第一步（Step 1/2）：前端调用 `/api/fetch-models` 接口实时从 anyrouter.top 拉取最新模型，同步更新前后端的模型列表，并在卡片上高内聚呈现 `testing` 状态。
   - 第二步（Step 2/2）：在最新获取到的模型基础上，前端并发调用 `/api/test-all` 批量进行测试，实时展现每个模型的可用性（Latency、报错摘要及预览）。
